# 绿色产品推荐系统架构设计

## 1. 系统整体架构

### 1.1 架构层次

系统采用分层架构设计，从上到下依次为：

```
 ┌─────────────────────────────────────────────────┐
 │                  交互层                          │
 │        Vue 3 Frontend (UI / Interaction)         │
 ├─────────────────────────────────────────────────┤
 │                  业务层                          │
 │        Flask Backend (Business Logic / API)      │
 ├─────────────────────────────────────────────────┤
 │                  算法层                          │
 │   Recommendation Engine / Clustering / ML Models │
 ├─────────────────────────────────────────────────┤
 │                  数据层                          │
 │      MySQL Database (Persistence / Storage)      │
 └─────────────────────────────────────────────────┘
```

1. **交互层**：前端Vue应用，负责用户界面展示和交互，包括用户端和管理员端两套界面
2. **业务层**：Flask后端应用，处理业务逻辑和API请求，作为前后端通信的桥梁
3. **算法层**：推荐算法和用户聚类模块，实现用户群体划分与个性化推荐
4. **数据层**：MySQL数据库，持久化存储用户、商品、行为、推荐结果等数据

### 1.2 模块划分

| 模块 | 职责 | 技术栈 |
|------|------|--------|
| 数据采集与预处理 | 数据加载、清洗、绿色标签标注 | Python, Pandas, NumPy |
| 用户特征与群体划分 | 特征提取、K-means聚类 | Python, Scikit-learn |
| 个性化推荐模型 | 协同过滤、基于内容推荐、价格加权推荐 | Python, Scikit-learn |
| 系统功能与展示 | 前端界面、API接口、数据管理 | Vue, Flask, MySQL |

### 1.3 架构设计原则

- **关注点分离**：各层职责明确，交互层只负责展示，业务层处理逻辑，算法层专注计算，数据层管理存储
- **松耦合**：层与层之间通过标准化API通信，任一层的修改不影响其他层
- **可扩展性**：算法层支持插件式扩展，可无缝接入新的推荐模型

## 2. 数据流转流程

### 2.1 用户行为数据流转

```
 User Action ──→ Frontend ──→ API ──→ Backend ──→ Database
                                                     │
                                              Update User Cluster
                                                     │
                                              Generate Recommendations
                                                     │
 User ←── Frontend ←── API ←── Backend ←────────────┘
```

1. 用户在前端进行浏览、购买、搜索等操作
2. 前端通过API将行为数据发送到后端
3. 后端将行为数据存储到数据库
4. 后端触发用户群体更新，重新聚类用户
5. 推荐算法根据用户群体和行为数据生成推荐结果
6. 前端展示推荐结果给用户

### 2.2 商品数据流转

```
 Admin ──→ Frontend ──→ API ──→ Backend ──→ Database
                                               │
                                        Auto-label Green Products
                                               │
                                   Match Products with User Needs
                                               │
                                Send Recommendations to Frontend
```

1. 管理员通过后端API添加商品和绿色标签
2. 后端将商品数据存储到数据库
3. 数据预处理模块自动标注绿色商品
4. 推荐算法根据商品的绿色属性和用户需求进行匹配
5. 推荐结果展示给用户

## 3. 核心模块设计

### 3.1 数据采集与预处理模块

- **功能**：加载公开数据集，清洗数据，标注绿色商品标签
- **流程**：
  1. 加载CSV格式的商品和用户行为数据
  2. 处理缺失值和无效订单
  3. 根据关键词自动标注绿色商品标签
  4. 将处理后的数据存入数据库

### 3.2 用户特征与群体划分模块

- **功能**：提取用户特征，使用K-means聚类划分用户群体
- **特征提取**：
  - 显性特征：购买绿色商品次数、搜索绿色关键词次数
  - 隐性特征：浏览母婴品类次数、评价中提及健康次数、购买低价高评分商品次数
- **群体划分**：
  - 主动绿色群体：直接购买绿色商品的用户
  - 潜在绿色群体：有隐性绿色需求的用户（如母婴用户）
  - 性价比绿色群体：关注低价绿色商品的用户

### 3.3 个性化推荐模型模块

```
                   ┌─────────────────────────────┐
                   │     User Behavior Data       │
                   └──────────┬──────────────────┘
                              │
                   ┌──────────▼──────────────────┐
                   │     K-means Clustering       │
                   │     (User Segmentation)      │
                   └──────────┬──────────────────┘
                              │
            ┌─────────────────┼────────────────────┐
            │                 │                    │
   ┌────────▼────────┐ ┌─────▼──────┐ ┌──────────▼──────┐
   │ Active Green    │ │ Potential  │ │ Price-sensitive │
   │ Group           │ │ Green Group│ │ Green Group     │
   └────────┬────────┘ └─────┬──────┘ └──────────┬──────┘
            │                │                   │
   ┌────────▼────────┐ ┌─────▼──────┐ ┌──────────▼──────┐
   │ Collaborative   │ │ Content-   │ │ Price-weighted  │
   │ Filtering       │ │ based      │ │ Recommendation  │
   └─────────────────┘ └────────────┘ └─────────────────┘
```

- **功能**：根据用户群体生成个性化推荐
- **算法设计**：
  - 主动绿色群体：协同过滤算法，基于相似用户的购买偏好
  - 潜在绿色群体：基于内容的推荐算法，匹配商品绿色属性与用户隐性需求
  - 性价比绿色群体：价格加权推荐，优先推送平价绿色商品
- **推荐策略**：
  - 推荐结果按匹配度和价格排序
  - 推荐模块故障时自动切换为热门绿色商品推荐

### 3.4 系统功能与展示模块

- **前端功能**：
  - 用户端：注册登录、推荐结果展示、行为记录、反馈提交
  - 管理员端：绿色标签管理、商品管理、用户分析
- **后端功能**：
  - API接口：用户管理、行为记录、推荐生成、数据管理
  - 数据持久化：用户、商品、行为数据的存储和查询

## 4. 数据库设计

### 4.1 表结构

- **users**：用户信息表
- **products**：商品信息表
- **green_labels**：绿色标签表
- **product_green_labels**：商品-绿色标签关联表
- **user_behaviors**：用户行为表
- **recommendations**：推荐结果表
- **user_feedback**：用户反馈表

### 4.2 实体关系

```
  users ────< user_behaviors
  users ────< recommendations
  users ────< user_feedback
  products ──< product_green_labels >── green_labels
```

- 用户与行为：一对多
- 商品与绿色标签：多对多
- 用户与推荐：一对多
- 用户与反馈：一对多

## 5. API设计

### 5.1 用户相关API

- POST /user/register：用户注册
- POST /user/login：用户登录
- POST /user/behavior：记录用户行为
- POST /user/feedback：提交用户反馈

### 5.2 推荐相关API

- GET /recommend/{user_id}：获取个性化推荐

### 5.3 管理员相关API

- GET /admin/labels：获取绿色标签列表
- POST /admin/labels：添加绿色标签
- GET /admin/products：获取商品列表
- POST /admin/products：添加商品
- POST /admin/products/{product_id}/labels：为商品添加绿色标签
- GET /admin/users：获取用户列表和统计
- POST /admin/import-data：导入数据
